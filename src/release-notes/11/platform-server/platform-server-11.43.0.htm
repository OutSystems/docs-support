Platform Server 11.43.0

Released on Aug 17, 2026

New in Platform Server 11.43.0

  • Updated System.Text.Json library bundled with the platform from version 8.0.5 to version 10.0.8. Also raises other Microsoft dependent libraries to be consistent at 10.0.8. (R11BCT-465)
  • Added support for Azure SQL Managed Instance (for the SQL Server 2025 engine and compatibility level 170). This applies to the platform database, as well as external databases.

    Configuration Tool and Service Center now feature a specific option for Azure SQL Managed Instance to improve setup clarity. (R11BCT-469)

  • Tentative fix for an issue that caused indexes to be created without dropping them first when using 2 stage deployment ( RPM-6830 Closed ). (R11BCT-511)
  • Added public, read-only Espace_CommitMessage entity, allowing access to messages added during publish. (R11BRT-2393)
  • Action Links now expose role="button" and support Space/Enter keyboard activation (Space activates on key release, matching native
  • Sortable Table column headers now expose aria-sort (none/ascending/descending) to communicate the current sort state to assistive technologies, and support the default-sort-direction Extended Property on the Header Cell to let custom OnSort actions declare a descending-first direction, when EnableWCAG22 is enabled, ensuring WCAG 2.2 (1.3.1 — Info and Relationships) compliance. (R11DT-3621)
  • ListItemSwipeable now exposes its swipe actions through a single-pointer alternative — right-click (context menu) on desktop and long-press (500ms) on touch devices — when EnableWCAG22 is enabled, ensuring WCAG 2.2 (2.5.7 — Dragging Movements) compliance for users who cannot perform dragging gestures. (R11DT-3622)
  • DropdownCustom now follows the ARIA combobox pattern (combobox/listbox/option roles, aria-expanded, aria-selected) when EnableWCAG22 is enabled, ensuring WCAG 2.2 (4.1.2 — Name, Role, Value) compliance for assistive technologies. (R11DT-3623)
  • List and ListItem widgets now expose explicit role="list" and role="listitem" (on non-semantic tags) when EnableWCAG22 is enabled, ensuring consistent screen reader behavior and WCAG 2.2 (1.3.1 / 4.1.2) compliance. (R11DT-3624)
  • Popover now follows the ARIA button/dialog pattern — the trigger exposes role="button", aria-haspopup="dialog", aria-expanded, and aria-controls (set only when expanded), and the popover content exposes role="dialog" and aria-modal="false" — when EnableWCAG22 is enabled, ensuring WCAG 2.2 (4.1.2 — Name, Role, Value) compliance for assistive technologies. (R11DT-3625)
  • Popup now exposes aria-label="Dialog" (unless the consumer provides aria-label or aria-labelledby) and invokes a new onEscape event when the user presses the Escape key while focus is inside the popup when EnableWCAG22 is enabled, ensuring WCAG 2.2 (4.1.2 — Name, Role, Value, and 2.1.2 — No Keyboard Trap) compliance for assistive technologies. To close the popup on Escape, wire the onEscape event to a client action that sets the visibility variable to False. (R11DT-3626)
  • Switch now exposes role="switch" and aria-checked (reflecting the current on/off state) when EnableWCAG22 is enabled, so assistive technologies announce it as a switch rather than a checkbox, ensuring WCAG 2.2 (4.1.2 — Name, Role, Value) compliance. (R11DT-3627)
  • The Upload widget's file input is now kept in the accessibility tree using a visually-hidden CSS pattern (instead of display: none) when EnableWCAG22 is enabled, so screen readers can announce it and keyboard users can reach it directly. The visible label no longer acts as a fake button — Enter/Space activation is handled natively by the input — and a focus ring is forwarded to the label via :focus-within so sighted keyboard users see where focus is. This ensures WCAG 2.2 compliance for 4.1.2 (Name, Role, Value) and 2.4.7 (Focus Visible). (R11DT-3774)
  • Button, Checkbox, RadioButton, and Switch widgets now enforce a minimum 24×24 CSS pixel interactive hit area when EnableWCAG22 is enabled, ensuring WCAG 2.2 (2.5.8 — Target Size, Minimum) compliance for touch and pointer-based interactions. (R11DT-3775)
  • Button, Input, Dropdown, Popover, and Popup widgets now remain usable at 200% browser zoom — fixed-height containers reflow with min-height + auto sizing, the popup minimum width collapses on narrow viewports (min(300px, 100%)), and overflowing dropdown rows stay reachable via vertical scroll — when EnableWCAG22 is enabled, ensuring WCAG 2.2 (1.4.4 — Resize Text) compliance. (R11DT-3776)
  • Dropdown, Popover, Popup, List, and Table Records widgets now fit within a 320px viewport without triggering page-level horizontal scroll — dropdown and popover panels clamp to the viewport edge, popup dialogs collapse their fixed minimum width on narrow viewports (min(300px, 100%)), lists wrap long item content, and Table Records scopes horizontal overflow to a keyboard-accessible scroll region — when EnableWCAG22 is enabled, ensuring WCAG 2.2 (1.4.10 — Reflow) compliance. (R11DT-3777)
  • Button, Dropdown, List, and TableRecords widgets now preserve content and functionality when users override text-spacing properties (line-height ≥ 1.5, letter-spacing ≥ 0.12em, word-spacing ≥ 0.16em) — overflow stays visible so text can grow beyond fixed heights, dropdown labels and options wrap instead of being clipped, and table cells use vertical-align: middle instead of line-height-based centering — when EnableWCAG22 is enabled, ensuring WCAG 2.2 (1.4.12 — Text Spacing) compliance. (R11DT-3778)
  • Button, Checkbox, Dropdown, Link, RadioGroup, Switch, and Upload widgets now reliably expose their visible label as part of the accessible name when EnableWCAG22 is enabled, ensuring WCAG 2.2 (2.5.3 — Label in Name) compliance for speech-input and assistive-technology users. (R11DT-3780)
  • Input and List widgets now expose dynamic updates to assistive technologies via ARIA live regions when EnableWCAG22 is enabled — Input validation messages are announced automatically through a role="alert" region kept in the DOM (no focus movement required), and List announces its current status ("N items", "No items", "1 item", "Failed to load items") through a visually hidden polite live region linked to the list via aria-describedby, with status text routed through the platform's TranslationsService so it can be localized — ensuring WCAG 2.2 (4.1.3 — Status Messages) compliance. (R11DT-3781)
  • TableRecords now accepts a table-caption extended property to render a element, an optional table-role="table" extended property to switch from role="grid" to native table semantics, and enforces a 24×24 CSS pixel minimum on sortable header cells; RadioGroup and CheckboxGroup now expose their validation message via aria-describedby (deduplicated against any developer-provided value); when EnableWCAG22 is enabled, closing WCAG 2.2 gaps for 1.3.1 (Info and Relationships), 2.5.8 (Target Size, Minimum), 3.3.1 (Error Identification), and 4.1.2 (Name, Role, Value). (R11DT-4047)
  • Popup widget now contains keyboard focus within open modal dialogs — Tab and Shift+Tab cycle only among focusable elements inside the popup, focus returns to the element that opened the popup when it closes, and the dialog itself becomes programmatically focusable (tabindex="-1") as a fallback for popups with no focusable children — when EnableWCAG22 is enabled, ensuring WCAG 2.2 (2.4.3 — Focus Order, 2.1.2 — No Keyboard Trap) compliance for keyboard users. (R11DT-4064)
  • It is now possible to configure how long Platform Server deployments wait for SQL Server table locks before failing. Three new settings in Factory Configuration let administrators raise the wait times used when schema changes hit tables that are already locked, preventing deployments from failing with the "Lock request time out period exceeded" error. Applies to SQL Server, Azure SQL, and Azure SQL Managed Instance. (RPM-6542) Publish Operation Deployment stage

Bug Fixing

  • Upgraded System.Security.Cryptography.Xml to version 8.0.3. It includes a security vulnerability fix introduced by that version. This change only affects the Server.API and the Server.Identity system applications, and the OutSystems services. (R11BCT-463)
  • Fixed an issue where translations were not applied for locales whose language code combines a script and a region (for example, Simplified Chinese for Singapore, zh-Hans-SG), causing screens to display text in the default language instead of the selected one. (RPM-3945) Service Studio
  • Fixed an issue that prevented a module from publishing when a Server Action used an Assign to copy a list (for example, the output of an Aggregate joining multiple Entities) into a Record List of an Entity, and the attribute mapping inside the Assign was set manually. (RPM-6639) Application Runtime Logic Execution
  • Fixed an issue where the Daily History tab in Service Center Analytics was not displaying any data on Oracle databases. (RPM-6861) Application Lifecycle Service Center
  • Fixed a scenario where native mobile binaries (apk, aab or ipa) would have 0 bytes upon downloading. (RPM-6871) Mobile Apps Builder Application Package
  • Updated OutSystems RabbitMQ plugin to improve compatibility with newer Oracle driver versions (23.26.x) (RPM-6876) Application Runtime
  • Fixed an issue that caused the Feedback Message in RichWidgets to instantly reopen after being dismissed. This occurred when accessing the application on a mobile device, where touch interaction delays or event bubbling mistakenly triggered the open sequence again right after the close action completed. (RPM-6891) Application Runtime System Components
  • License uploads in Service Center are now recorded in the General Logs, including details of which user performed the upload. (RPM-6932) Application Lifecycle Service Center
  • Fixed an issue that caused the Richwidgets/Input_Calendar to render with broken layout alignments. This occurred when developers used specific alignment configurations—such as left (“l”), right (“r”), or center (“c”) values—which failed to map correctly to the element's underlying positioning styles. (RPM-7002) Application Runtime System Components
