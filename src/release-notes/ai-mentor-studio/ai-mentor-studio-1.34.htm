AI Mentor Studio 1.34

This is a preliminary version of the document.

New in AI Mentor Studio 1.34

  • You can now remove your own association from an infrastructure directly on the Maintenance screen, without having to contact OutSystems Support. This self-service capability is available to users authenticated with an OutSystems account. (RADRT-1430)
  • Added a new v2 of the TechnicalDebt_Team method to the AI Mentor Studio REST API. This new version accepts a team Key as input, aligning it with the team key format used by LifeTime API v2. (RADRT-2983)
  • Improved the way probes are managed and distributed. AI Mentor Studio now automatically selects the most recent probe version compatible with your infrastructure when you download a new probe, and notifies you whenever a newer version is available. (RADRT-3080)
  • Locked and ignored modules are no longer analyzed, keeping them out of dropdowns, the canvas, and the Overview. (RADRT-3158)
  • Improved login performance when authenticating with the IT User method. (RADRT-3274)
  • Improved the Avoid setting Anonymous or Registered Roles to access Screens pattern to also analyze Human Activities. Findings are now raised when Anonymous or Registered roles are set on Human Activities, in addition to Screens. (RADRT-991)

Bug Fixing

  • Fixed an issue that allowed users with view-only permissions to change the analysis status of modules on the Ignore Modules list. Now, only users with the Change and Deploy Applications permission or higher can toggle a module's analysis status. (RADRT-2980)
  • Fixed an issue that caused the Foundation or Core module with screens pattern to incorrectly raise findings for non-public screens whose name ended with the _popup suffix. Now, the suffix is honored for both public and non-public screens. (RADRT-3109)
  • Fixed outdated URLs in the Japanese translation of AI Mentor Studio, namely in the steps shown on the Welcome Board screen for associating an IT user. (RADRT-3135)
  • Fixed an issue that caused the Forgot Password screen to incorrectly raise a finding under the Avoid setting Anonymous Roles to access Screens pattern. Now, this screen is excluded from the pattern's analysis. (RADRT-3159)
  • Fixed an issue that caused an "Index out of bounds" error when clicking the Allow all apps button on the Team strongly coupled with another team pattern. (RADRT-3161)
  • Fixed an issue that caused an error when changing the status of findings on the Duplicated Code pattern. (RADRT-3305)
  • Fixed an issue that prevented the Open in Service Studio button from working in Google Chrome. This occurred because spaces in the generated URL were not being correctly encoded. Now, the button works as expected on Google Chrome and other browsers. (RADRT-3306)
  • Fixed an issue that caused an incorrect finding count on the Overview screen when a finding was resolved and then reopened on the same day. Now, the Overview screen correctly reflects both actions. (RADRT-3353)
